Tier 1

Presentation tier: human–system interaction

Definition

The presentation tier is the visible interface through which authorized users enter, review, and act on ERP information.

Access channels

Web, desktop, mobile, kiosks, and dashboards provide controlled entry points.

Input validation

Required fields, formats, and basic checks prevent incomplete or invalid requests.

Role-based views

Menus and screens reflect assigned responsibilities and authorized functions.

Usability

Clear navigation and consistent forms reduce error and support process compliance.

Tier 2

Application tier: business logic and coordination

Definition

The application tier interprets user requests, applies business rules, coordinates workflows, performs calculations, and exchanges data with other systems.

Business rules

Policies, validations, limits, and posting logic determine how transactions are processed.

Workflow services

Tasks, approvals, notifications, and exception paths move work across roles and departments.

Integration services

Application programming interfaces and middleware connect modules, devices, and external platforms.

Calculation engines

Pricing, taxes, costing, allocations, and planning calculations are executed consistently.

Security enforcement

Authorization checks determine which operations a user or service may perform.

Transaction control

Related updates are completed together or reversed to protect data consistency.

Tier 3

Data tier: the shared enterprise memory

Data responsibilities

  • Store one controlled source for enterprise records.
  • Preserve relationships among customers, suppliers, items, accounts, employees, and transactions.
  • Enforce integrity through keys, constraints, authorization, logging, backup, and recovery.
  • Support operational reporting, analysis, and auditability.

Main ERP data categories

Master dataStable reference records used across processes
Transactional dataBusiness events recorded over time
Configuration dataRules, structures, parameters, and organizational settings
Audit dataWho changed what, when, and through which process

Deployment model 1

On-premise ERP: organization-managed infrastructure

Definition

On-premise ERP is installed and operated within infrastructure controlled by the organization or its designated local hosting environment.

Organizational control

The organization directs hardware, network, system configuration, update schedules, access controls, and physical security arrangements.

Internal responsibility

IT teams or contracted specialists manage availability, backup, recovery, monitoring, patching, and technical capacity.

Strengths

High configuration control, direct infrastructure governance, and close connection to local systems and devices.

Constraints

Higher capital requirements, specialist staffing needs, longer upgrade cycles, and direct responsibility for operational resilience.

Challenges and considerations

Architecture quality depends on coordinated technical and managerial decisions.

Security

Identity, authorization, encryption, monitoring, and incident response must cover every tier and connection.

Availability

Redundancy, backup, recovery objectives, and support arrangements protect essential operations.

Performance

Network latency, server capacity, database design, and workload patterns affect response time.

Scalability

Architecture must accommodate more users, transactions, modules, branches, and data without losing control.

Integration

Interfaces require clear ownership, data definitions, error handling, synchronization, and version management.

Governance

Decision rights, vendor oversight, configuration standards, and change control keep architecture aligned with goals.

Lesson summary

Session 3 key concepts

Three-tier structure

The presentation tier manages interaction, the application tier executes business logic, and the data tier maintains shared enterprise records.

Deployment choices

On-premise, cloud, and hybrid models differ in infrastructure ownership, control, scalability, connectivity, and management responsibility.

Architecture fit

Sound architecture aligns people, processes, data, technology, security, governance, and organizational objectives.
