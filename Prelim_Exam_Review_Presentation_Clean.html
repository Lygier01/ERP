Week 1 · Session 1

Introduction to Enterprise Resource Planning

W1 · S1
Key Concept

ERP is an integrated information system that connects major business functions through a shared database, enabling real-time data flow and coordinated planning, execution, and control.

Why ERP is needed

Duplicate workConflicting dataSlow reportsPoor decisionsWeak traceabilityScaling problems

Disconnected records create repeated encoding, inconsistent results, delayed visibility, and weaker control across operations.

1

Integration

One transaction can affect related functions automatically.

2

Shared database

Authorized modules use one controlled source of records.

3

Real-time processing

Updates are available without repeated manual consolidation.

4

Cross-functional scope

Finance, sales, inventory, HR, procurement, production, and more.

Remember

Enterprise = whole organization. Resource = money, people, materials, time, and information. Planning = coordination, decisions, forecasting, and control.

ERP is not only accounting software or one brand. It needs clean data, trained users, sound processes, management commitment, and maintenance.

Formula to remember

Net Requirement = Gross Requirement − Available Inventory − Scheduled Receipts

Source demonstration: 12,000 kg needed − 3,000 kg on hand − 0 scheduled receipts = 9,000 kg to order.

Important distinctions

Week 2 · Session 3

ERP Architecture and Deployment Models

W2 · S3
Presentation TierUser interface, input, role-based views
→
Application TierBusiness rules, workflows, calculations, services, security
→
Data TierMaster, transaction, configuration, audit, backup data
On-premise

Organization-managed

Local infrastructure and direct technical responsibility; usually greater customization control and longer preparation.

Cloud

Provider-managed

Provisioned service with internet access; usually faster deployment but dependent on provider capabilities and connectivity.

Hybrid

Shared environments

Selected components remain local while others use external services; integration scope determines complexity.

Important Distinction

Architecture explains how the interface, business logic, and data interact. Deployment explains where the system runs and who manages its infrastructure.

ERP Ecosystem and the Philippine Context

W4 · S7

→

→

Commercial ERP

Source examples: SAP, Oracle, Microsoft Dynamics, and mid-market suites. Emphasis: scale, structured support, and managed roadmaps.

Open-source ERP

Source examples: Odoo and ERPNext. Entry access is broader, but implementation, support, and technical governance are still required.

Selection principle

Choose for functional fit, cost, scale, support, and long-term sustainability—not popularity alone.

Philippine-context factors

Regulatory reportingMulti-branch visibilityInternet reliabilityTraining readinessLocal supportGrowth direction

Context in the lessons

Large organizations use full-scale ERP for high transaction volumes. Medium businesses adopt ERP as spreadsheets reach their limits. Cloud and open-source options widen access for smaller organizations.

Prelim master summary

Ready
Master summary

ERP integrates people, processes, data, technology, controls, and goals so the enterprise can plan, execute, monitor, and improve as one coordinated system.

Definitions and distinctions

  • ERP, shared database, integration, and real-time processing
  • MRP, MRP II, ERP, ERP II, and Cloud ERP
  • Architecture, deployment, master data, and transactional data
  • Finance, procurement, inventory, sales, production, HR, and CRM roles

Processes and applications

  • Why data silos create operational problems
  • The net requirement formula and result interpretation
  • Procure-to-pay and demand-to-cash module effects
  • How ERP creates efficiency, visibility, control, and strategic value
  • How context affects ERP platform selection

Key records

Customer, item, employee/user, purchase order, goods receipt, invoice, sales order, work order, AP, AR, and GL.

Key controls

Approvals, role-based access, validation, matching, segregation of duties, audit trail, and exception monitoring.

Enterprise-wide effect

One controlled event can update operations, inventory, customer or supplier records, financial accounts, audit trails, and management information.
